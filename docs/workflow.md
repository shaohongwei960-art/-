# 改编工作流

一首改编从想法到成品，建议按这六步走，每一步都有对应的文件落点。

## 1. 立项：复制模板

```bash
cp -r arrangements/_template arrangements/<曲目英文短名>
```

先把 `README.md` 的信息卡填完——尤其是**调性**和**人声音域**，这两项决定后面所有选择。

## 2. 分析原曲

- 扒出原始和声，写进 `chords.md`。
- 标出曲式：前奏 / 主歌 / 副歌 / Bridge，各多少小节。
- 找出「记忆点」：哪一句是全曲的钩子？改编时它必须保留或被更好的东西替换。

## 3. 定方向

先用一句话写清楚：**「把 A 变成 B，因为 C」**。
例：把这首抒情慢歌变成 Bossa Nova，因为想弱化悲伤感、适合咖啡馆演出。
方向定了，配器、BPM、和声复杂度就都有依据了。

## 4. 改和声 / 改词

- 改和声：在 `chords.md` 的「和声备选方案」表里对比原版与改版，写清楚**效果**。
- 改词：在 `lyrics.md` 里逐句标注字数和韵脚，中文还要检查**倒字**（字调走向和旋律走向别打架，比如四声字配上行旋律会听成别的字）。

## 5. 编曲

填 `arrangement.md` 的段落表。关键是**动态曲线**：不要从头满编制到尾，
Bridge 做减法、最后一遍副歌做加法（加声部、转调、加鼓 fill），落差才是听感。

## 6. 出活

```bash
python3 arrangements/<曲名>/build.py   # 生成 MIDI 到 build/
make audio                             # 可选：MIDI -> wav（需要 FluidSynth）
```

需要正式乐谱时，把 MIDI 导入 MuseScore 调整记谱，导出 MusicXML 存到 `score/`。

## 版权红线

- **公有领域**（如巴赫、帕赫贝尔）随便改。
- 现代作品：改词/改编属于演绎作品，**发布或商用前必须拿到词曲版权方授权**；
  翻唱平台的机械许可通常不覆盖「改词」和「大幅改编」。
- 不要把原唱录音的音频文件放进这个仓库。
