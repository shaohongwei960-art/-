# 前端后端 API 接入说明

## 当前状态

前端现在可以在两种**明确分开的**数据模式间工作：

- **本机演示模式：** 沿用 per-user localStorage 演示仓库，不会联系其他用户。未登录时默认使用；有登录会话且 API 已配置时，也可在顶部切回本机演示。
- **后端 API 模式：** 需要有效的认证会话和 `VITE_API_BASE_URL`。页面通过 `AuthGate` 传递 access token，并用 Bearer token 调用 `/api/v1`。状态栏会标识当前模式；失败时显示错误和重试入口。

这表示前端具备后端 API 接入路径，**不表示已有生产 API、云数据库、图片服务或大陆线上服务**。后端服务必须自行运行并配置认证、数据仓库和允许的 CORS 来源。

## 开发配置

可将以下内容加到未提交的 `.env.local`（仅用于本机开发）：

```dotenv
VITE_API_BASE_URL=/api
API_PROXY_TARGET=http://127.0.0.1:3000
```

在另一个终端启动本仓库后端；Vite 会把浏览器的 `/api/*` 请求转发至 `API_PROXY_TARGET`，避免浏览器直接访问 localhost。目标服务应提供本仓库 `server/app.mjs` 中的 `/api/v1` 路由。

也可以让 `VITE_API_BASE_URL` 指向 API 公网/内网 origin（例如 `https://api.example.com`，或带 `/api` 的地址）。跨域部署时须在后端配置精确的允许来源和 HTTPS。请不要把密钥、服务角色 token、短信/邮件凭证放入任何 `VITE_*` 变量；前端只应包含适合公开的认证 SDK 配置。

只有同时满足「已登录且拿到 access token」与「API URL 已配置」，前端才启用服务器模式。未配置认证、未登录或无 API URL 时，仍使用本机演示，不会假装同步。

## 已连接的交互

- 登录用户的个人资料读取和编辑（昵称、国家/地区代码、城市、界面语言）。
- 公开物品列表、自有物品、收藏、本人已发评价、本人举报记录及黑名单加载。
- 新建/修改物品、下架和恢复；修改后重新进入审核状态，列表/详情会显示审核状态。
- 收藏/取消收藏、发起交换、接受/拒绝/撤回、交接确认、评价。
- 打开会话、加载消息、发送消息、举报、拉黑。
- 交换物品快照从服务端 offer 响应加载，以便历史物品下架/换出后仍显示。

首屏读取采用 REST API；聊天目前通过 REST 发送与加载，不是 WebSocket/实时推送。操作失败会将后端错误转为 UI 提示；收藏为乐观更新，其余流程仅在请求成功后更新页面状态。

## 图片存储限制

图片对象存储仍未接入。后端模式的发布/编辑界面已明确提示：所选图片仅作浏览器预览，当前 API 使用 `prototype/placeholder/<category>.jpg` 占位对象键；不会上传用户选中的文件。真实上线前必须接好受控上传、类型/大小校验、图片处理和签名访问，并替换占位图片键；不要把 data URL 或本机文件路径当作服务端图片。

## 后端及大陆环境限制

- 后端目前包含 Fastify API、内存测试仓库和 PostgreSQL 仓库实现；PGlite 测试通过不等于已完成真实 PostgreSQL 部署、并发/备份/恢复验收。
- 生产认证须提供能向后端验证 JWT 的服务；浏览器 Supabase 配置本身不替代服务端身份验证。
- 大陆正式部署仍需单独选定并核实境内认证、数据库、对象存储和 API 接入服务及数据驻留要求。不得把海外托管误当作大陆生产方案。
- SMS/email、对象存储、数据库供应商、客服/申诉运营台和生产监控尚未选型或验收。当前没有真实云端凭证、生产地址或备案/应用商店发布结果。

验证前端和服务端基础：

```sh
npm test
npm run build
```

浏览器自动化测试仍受当前环境缺少 Chromium 系统共享库影响，详见 README。API 单元/PGlite 集成测试不能替代真实云服务和真实设备验收。
