# 换换｜简化版产品方案

> v0.2 · 2026-10-08 · 当前设计方向  
> 根据最新讨论，以本版为准。v0.1 保留为后续参考，不作为第一版功能清单。「换换」为暂用名。

## 1. 就做一件事

**像逛二手平台一样找东西，用自己的闲置换，而不是花钱买。**

沿用用户熟悉的搜索、分类、物品详情、发布、聊天和订单记录，不先做积分体系、自动估价、复杂匹配或社区运营系统。

## 2. 把买卖流程改成交换流程

| 常见购物／二手平台 | 我们的平台 |
| --- | --- |
| 发布商品、填写价格 | 发布闲置、填写“想换什么” |
| 浏览、搜索、收藏 | 保留这些操作 |
| 立即购买 | “我想换”——选择自己的物品，发送交换申请 |
| 联系卖家 | “聊一聊”——可以先了解物品再申请 |
| 下单付款 | 对方接受申请，双方物品进入“交换中” |
| 订单记录 | 交换记录，展示“我提供的”和“对方提供的” |
| 确认收货、评价 | 实际交接后各自确认，双方完成后互评 |

是否值得换，由双方决定；平台不强求价值相等。首版建议实物直换，不加入现金补差。

## 3. 五个入口就够了

**首页｜消息｜发布｜交换｜我的**

- **首页：** 搜索栏、分类、推荐／附近／最新、双列物品卡片。卡片展示图片、标题、区域和“想换什么”，不展示价格。
- **消息：** 围绕物品聊天；交换申请也以卡片出现在会话中，能点开查看和处理。
- **发布：** 照片、标题、分类、成色与瑕疵、所在区域，以及“想换什么”；不知道换什么可以选“都可以，聊聊看”。
- **交换：** 收到的申请、发出的申请和交换记录；展示待回复、交换中、已完成、已结束。
- **我的：** 我的物品、收藏、个人资料、评价和设置。

物品详情沿用熟悉布局：大图、标题、说明、成色、区域、发布者信息。底部保留两个主按钮：**聊一聊／我想换**。

## 4. 一个完整例子

你发布一台闲置咖啡机，写“想换露营用品，也接受其他提议”。

另一位用户看到后，点击“我想换”，选中自己已发布的帐篷并发送申请。你可以看帐篷详情、聊天、接受或拒绝。接受后，两件物品都标记为“交换中”。

双方约定交接，检查实物并自愿交换。各自确认实际交接完成后，两件物品标记为“已交换”，双方可以评价。

第一版先做一件换一件。没有发布物品也能浏览和聊天，到正式申请时再引导发布。

## 5. 只保留必要规则

1. **接受前自由选择：** 可收到多个申请，申请人可撤回，对方可拒绝。
2. **接受后不重复交换：** 一次接受必须同时锁住双方物品；只要其中一件不可用，整笔申请就不能接受。
3. **条件不能悄悄改变：** 申请保存物品资料版本，重要信息有变化需重新申请；接受后不能直接改换物品。
4. **没有交接可以退出：** 无人声明已交付且没有争议时可取消并释放物品；已有一方声明交付或有争议则转入问题处理，不自动解锁或假定完成。
5. **基本安全不省略：** 如实说明瑕疵，不公开具体住址，提供举报和拉黑；后台具备简单的内容审核与问题处理能力，不允许违禁物品。

这些规则由系统承担，不需要用户学习一套复杂玩法。

## 6. 可以做得更好的三个小细节

- **“想换什么”比价格更显眼：** 用户不必每次开口问。
- **申请卡片同时展示双方物品：** 一眼看懂这次用什么换什么。
- **交接后轻提醒：** 提醒未确认的一方处理，不自动生成完成记录或好评。

首版推荐按类别、区域和发布时间即可，不依赖复杂算法。

## 7. 首版边界

**做：** 基本账户、浏览搜索、收藏、发布、聊天、交换申请、交换记录、完成确认、评价、举报和必要后台。

**暂不做：** 积分、估价、支付、现金补差、多方交换、双方多件组合、直播、会员、广告和自动赔付。

交接方式尚未由用户最终确定。为让第一版简单可靠，建议先支持同城见面，不把系统支持的邮寄流程放进首版；界面不把私下邮寄描述为有平台保障。

## 8. 下一步

按照上述五个入口设计可点击原型，先把“逛物品 → 发布 → 聊天 → 申请交换 → 完成”的体验做顺。不再把市场研究、复杂商业模式或大规模试点计划作为画页面前的前置任务。
